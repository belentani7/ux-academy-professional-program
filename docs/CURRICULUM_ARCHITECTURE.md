# Arquitectura curricular — UX Academy

## Propósito y principio académico

UX Academy forma diseñadores capaces de investigar, decidir, prototipar, evaluar y comunicar soluciones digitales bajo restricciones reales. El recorrido no presenta un proceso lineal como receta: las etapas de descubrimiento, definición, desarrollo y entrega se revisitan al aparecer nueva evidencia, tal como plantea el marco Double Diamond del Design Council.[1] La práctica se estructura mediante problemas auténticos, artefactos revisables, retroalimentación formativa y evidencias acumulables en un portafolio.

La arquitectura toma como referencia pública las competencias de investigación, wireframing, prototipado, evaluación e inclusión que aparecen descritas por el programa UX de Google, pero el contenido, los casos, las evaluaciones y las plantillas de esta plataforma serán originales y no afiliados.[2] El programa interno no emite créditos académicos ni certificación oficial de ninguna empresa.

## Resultado de aprendizaje del programa

Al completar el programa, la persona podrá justificar decisiones de producto con evidencia, producir un sistema de diseño accesible, probar hipótesis con usuarios, colaborar en la entrega a desarrollo y presentar un caso de estudio profesional. Tendrá cinco evidencias de portafolio: una aplicación móvil, una experiencia web responsive, un producto con complejidad media, una iniciativa de product design y un capstone de extremo a extremo.

## Estructura repetible de cada módulo

Cada módulo seguirá una misma arquitectura didáctica para facilitar orientación, sin repetir el contenido. Abrirá con una situación profesional y objetivos observables; continuará con conceptos, decisiones y ejemplos; incluirá un caso aplicado, práctica guiada y práctica individual; cerrará con un quiz, una revisión mediante rúbrica, un mini proyecto, un glosario y una lista de competencias. La lección individual siempre indicará qué es un concepto, por qué importa, cuándo conviene utilizarlo, cómo aplicarlo, un error frecuente y su uso profesional.

| Bloque | Propósito | Evidencia de dominio |
|---|---|---|
| Enmarcar | Conectar el tema con una tensión de producto real | Hipótesis o decisión inicial |
| Comprender | Enseñar conceptos con ejemplos y contraejemplos | Quiz de recuperación activa |
| Practicar | Aplicar un método con apoyo progresivamente menor | Artefacto parcial o respuesta razonada |
| Revisar | Contrastar el trabajo con criterios explícitos | Autoevaluación y feedback del mentor |
| Transferir | Aplicar la habilidad a un proyecto o caso nuevo | Entregable evaluable de portafolio |

## Itinerario de proyectos

**Proyecto 1 — Pulse:** Una aplicación móvil de acompañamiento de hábitos para personas con poca disponibilidad de tiempo. El alcance permite practicar problemas, flujo, estructura de tareas, wireframes y la primera versión de un prototipo.

**Proyecto 2 — Civic Desk:** Una experiencia web responsive para solicitar, seguir y resolver incidencias comunitarias. Obliga a traducir necesidades distintas a navegación, formularios, estados de error y comportamientos entre móvil y escritorio.

**Proyecto 3 — Field Notes:** Un producto colaborativo para documentar visitas de campo. El foco es la coherencia del sistema: foundations, componentes, estados, tokens, responsive y handoff.

**Proyecto 4 — Product Design Challenge:** Una mejora de activación para una plataforma de aprendizaje con abandono temprano. La persona define outcome, identifica oportunidades, prioriza hipótesis y propone un experimento con métricas de éxito y riesgos.

**Capstone — Open Brief:** Un problema abierto seleccionado desde un conjunto de sectores de bajo riesgo. Exige investigación responsable, definición, arquitectura, wireframes, UI, sistema de diseño, prototipo, pruebas, iteración, caso de estudio y presentación. No incluye una solución predeterminada; la evaluación se centra en el razonamiento, evidencia y calidad del proceso.

## Evaluación y certificación interna

La calificación se compone de comprobaciones breves, prácticas, proyectos, examen final y capstone. El nivel se comunica con rangos consistentes: insuficiente (0–59), aprobado (60–69), competente (70–79), avanzado (80–89) y excelencia (90–100). Las rúbricas evalúan investigación, definición, arquitectura, wireframes, UI, accesibilidad, responsive, testing, documentación y comunicación; cada dimensión distingue desempeño **novato**, **competente**, **avanzado** y **profesional**.

El *Certificate of Completion — UX Design Professional Program* queda disponible cuando la persona completa el 100 % de las lecciones obligatorias, obtiene al menos 70/100 en la nota compuesta, aprueba el examen final con al menos 70 %, entrega los cuatro proyectos y aprueba el capstone con nivel competente o superior. La plataforma mostrará estas condiciones antes de presentar cualquier certificado.

## Trilingüismo editorial

El contenido se publica en español, português e inglés mediante fichas editoriales equivalentes, no mediante traducción automática en tiempo de ejecución. Cada ficha utiliza los mismos identificadores de módulo, lección, competencia y evaluación para asegurar que el progreso se conserva al cambiar de idioma. Un glosario base normaliza términos de práctica internacional y explica diferencias locales cuando haya una traducción útil.
